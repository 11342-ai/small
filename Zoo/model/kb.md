# 知识库层（KB）设计稿

> 位置：`internal/kb`（叶子包）+ `~/.small/kb/` 文件树
> 状态：核心包 + 工具层已实现（2026-08-29；`internal/kb`：解析/边/反链/无环/受控写入；builtin `kb_tree`/`kb_refs`/`kb_check`/`kb_write`）
> 关联：`model/memory.md`（并列层）、`model/tool.md`（工具三件套）、`路线图.md`（doc 工具合流）
> 决策基调：md 文件树是唯一事实来源，索引全派生不落盘；goldmark 纯 Go AST 解析（无 cgo）；无环只约束结构边。

## 1. 定位与结论

知识库是 memory 之上的并列层：memory 管"可检索的文本"，KB 管"有结构、可导航、有深浅的知识网络"，人和 agent 共用一份 md 文件树。

格式上限一句话：纯 md 文件树 + 相对路径链接（带 #锚点）+ YAML frontmatter 标记，不支持任何自定义语法。

三句话骨架：段落是节点（`path#heading`），文件是容器；树管层级（单父无环），tag 管横切（多域），链接管引用（成环允许，反链呈现）；深浅由内容结构派生，不手填。

## 2. 存储布局

```
~/.small/kb/              # 默认目录，与 memory 并列；后期需要时加 config（SMALL_KB_DIR）限定
├── Java/ 数据/ 中间件/ …          # 大主题簇分夹，纯归置，不承载归属语义
│   └── 数据/延迟双删.md           # 跨域知识点只写一份，放主主题夹
```

节点表、边表、反链、tag 注册表全部运行时派生、不落盘，工具调用前按文件 mtime 惰性重建（对齐 memory 的惰性刷新）。物理层与逻辑层彻底分离：文件夹管归置——命名与位置由用户自由处理，只按物理容量分（超量自化为新夹），不承载任何语义；tag 管归属（domains 多值），链接管引用，树管递进，语义全在元数据层。跨域知识点只写一份放任意夹子，靠 domains 聚合。文件移动/重命名由工具完成并自动重写引用（正链反链一起改）防断链；用户手工移动后由 kb_check 断链扫描报告修复。Zoo/ 保持设计文档性质，不纳入 KB 索引；agent 要看 Zoo/ 走 doc 工具，不经 kb。

## 3. 数据模型

### 3.1 节点

节点 = `path#heading`（段落），文件是容器。domains 是文件级字段；段落级"涉及某知识点"一律用链接表达，段落不设 tag。frontmatter 字段最小集：domains（文件级域列表，即头节点大方块；跨域知识点如延迟双删列多个域）、level（认知深度 1-5，由段落结构派生，手填仅作覆盖）、status（draft/stable）、parent（结构父，仅派生错误时显式覆盖，逃生舱）。

### 3.2 边

统一边表 `(source, target, kind, status)`，运行时派生，供环检测、删除检查、断链扫描、图谱可视化共用。

结构边 structure：父子关系，目录不参与派生。文件内靠标题层级（## 段落挂到最近上级标题）；文件间递进不硬建树，靠 reference 链接 + 反链呈现阅读路径；显式 parent 仅派生出错时覆盖（逃生舱）。无环约束只作用于此：写时快速校验（父链不含自己即合法），违规业务层报错；kb_check 全库批处理兜底，防手工改文件绕过。

引用边 reference：正文相对链接 `[x](path#heading)`。允许成环，靠反链索引呈现。链接格式定相对路径，明确不做 wiki-link 短名、不做稳定 ID：短名需文件名唯一 + 解析查索引，ID 需第二张词表，两者对当前规模不值；agent 自动补链 + 移动重写工具足以保证链接可用。

### 3.3 tag 注册表

tags.md 受控词表，平铺一维、无层级。agent 写知识先查表，新 tag 必须上报用户确认才入表（审批式增长，防漂移）。不用层级 tag：结构树已分层，tag 再分层是重复维护；跨域靠多 domains + 引用链接表达。域导航由 kb_tree 按 domains 自动聚合，物理文件不需要按域归入对应夹。

## 4. 解析引擎

goldmark 纯 Go AST，无 cgo——"零新增依赖"红线在此破例一次，理由：升级路径本就在等 md 解析器，且 goldmark 成熟、Hugo 同款。提取规则做成数据驱动的规则表，每条 (Kind, CaptureName, Matcher)，现四种：heading（节点）、link（引用边）、frontmatter（domains/level/status/parent）、tag。规则表与 tree-sitter 查询（.scm）功能等价（声明式提取 + 命名捕获），只是形态从 s-expr 文本变为 Go 数据；对 md 所需的四种提取足够，用不上查询语言表达力。temp_go.scm 一类是对源码做索引（语法树），与知识库（md 文档）是两个场景，goldmark 只服务后者，将来要索引源码再评估 tree-sitter。新增提取模式 = 加一行规则、不改代码，保留 .scm"规则是数据"的初衷。

## 5. 深浅

level 由"深度段落词表"派生，不用缺省值：

L1 定义 → L2 示例/操作 → L3 原理 → L4 失效/边界/权衡 → L5 演进/对比/批判。

节点出现了哪个最高档的段落，level 就是几。kb_check 自动比对派生值与 frontmatter 覆盖值，不一致上报。深浅是派生值不是存的数字；L4（失效/边界）是最强深浅信号，也是自动判深的标准——只背定义无失效段的节点，深不了。

## 6. 删除协作

kb_refs 反链报告节点被谁引用，用户四选一：保留 / 改指到其他节点 / 级联删子树 / 断链并标记 broken。删父节点时子节点处理（重挂/级联/脱钩）同样问用户。反链数据同时是断链扫描与图谱可视化的来源。

## 7. 工具与合流

kb_tree：结构树查询（parent/子树/深度）+ 按 domains 自动聚合域视图（大方块导航），用户与 agent 共用。
kb_refs：反链报告，删除检查入口。
kb_check：全库巡检——无环、断链、孤儿（无引用也无被引用）、重复标题、新 tag、标题层级跳变、level 与段落比对、补链建议（段落出现某知识点但无对应链接时上报）。

链接维护自动化：写入时 agent 自动识别正文涉及的知识点并补链接（提示词约束）；移动/重命名工具自动重写正链与反链；kb_check 扫描漏链。链接由机器维护、人抽查，把双链知识库常见的人肉维护成本降到最低。

与路线图 doc 工具（file_read/doc_search）合流：共享底层 kb 包，工具走三件套模板；将来模块规模扩大可独立拆分，接口天然可拆，届时重复也无所谓。

## 8. 边界红线

- md 是唯一事实来源，索引全派生不落盘；不发明自定义语法，正文 `|` 标记一律落 frontmatter。
- 无环只约束结构边；引用边允许成环。
- 深度只定义在结构边（树）上；引用边成环无深度概念。将来"why 追问链"（5-why 原则）做成结构边 kind，原因先于结果天然无环——本期不做。
- 依赖单向：kb 是叶子包，只依赖 stdlib + goldmark；builtin 工具结构注入，agent 零改动。
