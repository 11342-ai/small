> 时间：2026-08-23
> 范围：`internal/memory` 模块全生命周期（存储/检索/工具/装配）+ `memory_save` 受控写入增强 + `get_current_time` 时间工具 + `WithToolObserver` 工具观测 + 工具形态统一

> 关联：`Zoo/model/memory.md`（模块设计）、`Zoo/路线图.md`（trace 边界）、`CLAUDE.md`（约定与决策表）、`Zoo/model/总结-tool-260823.md`（工具模块前置会话）

## 1. 本会话解决的问题与边界

### 1.1 问题

为 DeepSeek 多轮对话 CLI 添加**跨会话长期记忆**（简化版：文件 + 关键词检索，不上向量），并以"工具暴露"形态给模型使用；随后补齐工具体系：受控写入（`memory_save`）、时间感知（`get_current_time`）、工具调用可观测（`WithToolObserver`）。全程保持项目既有原则：**依赖单向、解耦到隔离点、功能需求决定形态、零新增依赖**。

### 1.2 问题边界

| 模块 | 职责 | 明确的"不做什么" |
|---|---|---|
| `internal/memory`（叶子） | Markdown 记忆文件（`MEMORY.md` + `memory/*.md`）分块建索引；bigram + 子串兜底 + 轻量 BM25 检索；惰性刷新 | 不 import 任何内部包；不感知 provider/session；不做向量/蒸馏 |
| `memory.Append` | 受控追加，**路径锁死只写归档层** `memory/*.md` | 常驻层 `MEMORY.md` 无人手维护以外的写入路径 |
| `tool/builtin` | 三个记忆工具 + 时间工具，一工具一构造函数 | 生产代码不反向依赖 agent/session/provider/config（imports_test 固化） |
| `agent` | `WithToolObserver` 回调（nil-safe），Run 每实际执行一个工具触发一次 | 循环逻辑零改动；观测只透传事件不落盘 |
| `main` | 组合根装配 + 启动注入（MEMORY.md 进 system prompt）+ 实时展示 | 工具清单不写死在 main（register.go 集中持有） |

依赖方向（新增部分）：

```
main → agent → tool
        ↘ builtin → memory（叶子）
```

**明确不做（YAGNI / 规模不匹配）**：向量/语义检索、后台蒸馏、模型自主写入（仅显式要求受控写入）、auto-recall 每轮注入、会话 JSONL 索引、工具轨迹落盘（仅事件源就绪）。

## 2. 分歧与结论

### 2.1 记忆写入侧（本会话最大的方向演进）

- **分歧**：阶段一定稿为"人手写 md（纯只读索引）"，CLAUDE.md 决策表据此记录；后用户提出"能不能做 memory_save 让模型自己写"。
- **演进**：并非推翻旧决策，而是把"内容质量控制从人转移到模型"的风险**显式化并用设计缓释**——双层隔离（常驻层人手维护、归档层可受控追加）+ 触发约束（system prompt 双重限定"仅用户明确要求时写入"）。
- **结论**：`Append` 在 **memory 包层**就锁死只写归档层（工具层无写入常驻层的任何手段），"写得再烂也只进搜索池"。
- **决策依据**：常驻上下文（启动注入）是稀缺资源，必须人手把关；归档层（检索池）容忍噪声，检索质量由相关性评分兜底。红线是"防污染"，不是"禁止写入"。

### 2.2 工具构造形态：集合构造函数 vs 一工具一构造函数

- **分歧**：我最初用 `MemoryTools(mem) []tool.Tool` 一个集合构造函数打包 search/get 两个工具（省两行 append）；用户指出与 `Echo() tool.Tool` 形态不一致。
- **结论**：拆为 `MemorySearch(mem)` / `MemoryGet(mem)` / `MemorySave(mem)`，register.go 显式列出全部内置工具。
- **决策依据**：内置清单"集中持有"约定要求 register.go 一眼可见完整工具集；**一致性优先于省两行**——返回切片让清单被 `[]tool.Tool` 遮蔽。

### 2.3 执行逻辑内联 vs 外置

- **分歧**：用户问"为什么执行函数被迫写在 NewFunc 参数里？能不能外面写好再引用"。
- **澄清**：`NewFunc(spec, run)` 的 run 签名固定为 `func(ctx, args)` **不含 mem**，执行逻辑拿仓库实例只能靠闭包捕获——所以"完全外部引用"不可行，只能**外置具名函数 + 一行转发闭包**。
- **结论**：`runMemorySearch(mem, args)` / `runMemoryGet` 外置为包级函数（可脱离工具壳独立单测），NewFunc 内留转发。
- **决策依据**：以复杂度为尺——echo 的 run 5 行内联（`http.HandlerFunc` 惯例），记忆工具 run 25 行值得外置；工具构造器外部形态两边一致。

### 2.4 工具轨迹是否写入 session

- **分歧**：用户问"未来能否把工具使用情况写入 session，市面有没有这么做"。
- **澄清**：**工具调用的本体（名称/参数/结果）已随会话历史落盘**（`assistant.ToolCalls` + tool 结果，续聊回灌必需，市面主流同款）；缺的是**元数据**（耗时/顺序/审计）。
- **结论**：trace 元数据**独立成文件，不写 session**——session 语义是"回灌模型的对话历史"，混入耗时/审计会污染模型输入；市面同款分离（对话消息 vs Harness trajectory / Codex rollout 元数据）。事件源复用 `WithToolObserver`。
- **决策依据**：关注点分离——会话（给模型） vs 轨迹（给人/调试）。

### 2.5 测试 import agent 是否破坏隔离点

- **分歧**：builtin 的端到端测试 import `agent`，用户担心破坏依赖单向/隔离点。
- **澄清**：测试代码只进测试二进制，**不参与生产依赖图**（与 agent/imports_test.go 的"测试可自由 import"同一约定）；生产代码依赖未变。
- **结论**：新增 `builtin/imports_test.go` 把"生产代码不得反向依赖 agent/session/provider/config"固化为合并门槛；CLAUDE.md 新增红线 6。

## 3. 踩坑记录（忽视临界情况的代价）

### 3.1 MEMORY.md 注入按字节截断切坏 UTF-8

- **现象**：`loadBootstrapMemory` 第一版 `s[:2000]` 按**字节**截断，中文字符被拦腰切出非法 UTF-8（测试当场抓到：`truncated length = 2058`）。
- **根因**：中文 3 字节/字符，字节截断不保证落在字符边界。
- **解决**：改按 rune 截断（`[]rune(s)[:limit]`），测试补 `utf8.ValidString` 断言兜底。
- **教训**：涉及中文/多字节文本的截断必须按 rune，不能按字节。

### 3.2 测试断言块号凭直觉

- **现象**：builtin 测试断言 search 命中 `MEMORY.md#1`，实际是 `#0`（文件只有一个 `##` 标题，头部为空 → 无块 0 以外编号）。
- **解决**：修正断言为 `#0`。
- **教训**：Ref 块号由分块规则决定（首个标题前为块 0），断言前先按分块规则推导，别凭直觉。

### 3.3 CLAUDE.md 被对话输出污染

- **现象**：验证输出（"gofmt 无输出 / go test 全绿..."）被混入 CLAUDE.md 的示例代码块。
- **解决**：人工清理污染行；git 提交前 `git diff` 核对文档。
- **教训**：markdown 文档不在编译/测试范围，污染靠编译发现不了——提交前必须人工核对文档 diff（尤其与对话输出相邻的文档）。

### 3.4 中文检索必须分词（设计层提前规避，未踩坑）

- **临界情况**：中文无空格，朴素按空白分词对中文全失效（"我们决定用 JSONL"会被切成一整词）。
- **处理**：bigram（二元组）分词 + 子串兜底 + 轻量 BM25；切分跳过空白/标点，查询与文档两侧规则一致。
- **结果**：测试先行（中文查询/标识符/多词排序均锁住），未踩坑；词典分词（sego/jiebago）留作召回质量升级路径。

### 3.5 `embed` 概念澄清（非坑，认知纠偏）

- **困惑**：用户问 Go `embed` 是否适合记忆存储。
- **澄清**：`embed` 是**编译期只读快照**（改文件需重新编译），记忆是**运行时动态增长**数据——语义错位，不适用；归属部署/打包层。

## 4. 后续开发的统一与连贯性

以下条目为后续开发硬性对齐项（核心已写入 CLAUDE.md）：

1. **工具形态统一**：一工具一构造函数（`Echo()` / `MemorySearch(mem)` 同款）；执行逻辑超 10 行外置具名函数 + 一行转发闭包；`tool.NewFunc` 组装，零新抽象。
2. **存储部件同构**（session / memory）：叶子包、`New(dir)` 模块对象、不接口化、防路径注入（白名单校验）、单文件容错、惰性/按需读取。
3. **行为开关 Option + nil-safe 回调**：`WithToolObserver` 是第二个回调先例——回调字段可 nil，调用前判 nil，不注入零感知。
4. **依赖纪律**：builtin 生产代码只 import `tool`/`memory`（imports_test 固化，CLAUDE.md 红线 6）；测试可自由 import 做端到端。
5. **双层记忆 + 双轨注入**：常驻层（人手维护、启动注入、2KB 预算） vs 归档层（受控追加、按需检索）；高频事实必见、低频按需深挖。
6. **展示层**：rune 安全截断摘要（防长结果刷屏 + 防切坏 UTF-8），失败带 `[失败]` 标记。
7. **失败语义**：工具执行失败统一 `Result.IsError` 业务失败回灌，框架错误才中止（`WithToolObserver` 只在实际执行后触发）。
8. **文档先行 + 决策同步**：新模块先写 `Zoo/model/*.md`，决策落地同步 CLAUDE.md 决策表与路线图勾选。
9. **节点提交 git**：每完成一个最小可行实现即提交（本会话三次提交，见 §5）。
