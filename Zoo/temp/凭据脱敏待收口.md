## 1. 待收口：`web_fetch` 的错误文案（同类问题，非 k8s 面）

位置：`internal/tool/builtin/web.go`

| 行 | 文案 | 会不会带 userinfo |
|---|---|---|
| :55 | `参数错误: ` + err | 否（`json.Unmarshal` 的错误不回显 URL） |
| :68 | `请求构造失败: ` + err | **会**（`http.NewRequestWithContext` 的 `*url.Error`） |
| :76 | `抓取失败: ` + err | **会**（`http.Client.Do` 的 `*url.Error`，最常见） |
| :86 | `读取失败: ` + err | 一般不会（body 读错误）；成本为零，可一并套 |

- 触发：用户在对话里给出带 basic-auth 的 URL（`https://user:pass@host/path`）。`runWebFetch` 只校验 scheme，
  `u.String()` 原样保留 userinfo 交给 http client。
- 后果：错误原文进 `tool.Result.Data` → 模型上下文、session 落盘、trace、控制台。
  password 已被掩成 `***`，**username 明文**。
- 判据冲突：红线是"机密绝不入库"，且 k8s 面已按同一判据封了——两面口径不一致。
- 最小改动：:68/:76（可选 :86）套文本脱敏。

## 2. 待收口（更严重）：工具入参原样落盘，凭据是**全明文**

与 §1 不同：泄露的不是错误里的 URL，而是模型传进来的参数本身，password **没有**被掩码。

已验证的三个落点：

| 落点 | 位置 | 内容 |
|---|---|---|
| 控制台 | `main.go:287`（`fmt.Printf("→ %s(%s)…", ev.Name, truncate(ev.Args, 120))`） | `Args` 截断 120 字符 |
| trace 文件 | `main.go:465` → `internal/trace/trace.go:30-31`（`Args string`，json tag `args`） | `~/.small/sessions/<id>.trace.jsonl`，**原文** |
| session 文件 | `internal/session/session.go:34,44`（`ToolCalls[].Args`，字段注释写明"原始形态"） | `~/.small/sessions/<id>.json`，**原文** |

- 触发同上：`web_fetch` 的 args 是 `{"url":"https://user:pass@host"}`，明文落三处。
- 性质：这是**设计口径冲突**，不是 bug——trace/session 明确以"原样、可审计"为目标
  （见 `internal/trace/trace.go` 包注释、`session.go:43`）。但"原样"与"机密绝不入库"在带凭据 URL 上直接对撞。
- 波及面不止 `web_fetch`：任何入参含机密的工具都同理（如把密钥写进 `memory_save` / `file_write` 的内容）。
  所以这条不该按"给 web_fetch 打补丁"来做，要按"入参落盘策略"整体决策。

### 备选方案（选定一个再动手）

- **A. 落盘前对 `Args` 做脱敏**：agent 层或组合根在写 trace/session 前过一遍。
  问题：拿不到"哪个字段是机密"的语义，只能做通用文本脱敏（如 URL userinfo），对自由文本无效；
  改动面大（动 session/trace 两个叶子包的契约）。
- **B. 只做通用文本脱敏（与 §1 同一件）**：把文本脱敏应用到 `Args` 再落盘/打印。
  能挡住 URL 凭据这一类，成本低；对自由文本里的密钥无效，但至少口径统一。
  代价：trace/session 的"原文可审计"属性被削弱——需同步改三处注释与 `Zoo/model/trace.md` / `session.md`。
- **C. 显式不处理，写入决策记录**：承认"入参原样落盘"是既定契约，
  把"不要把凭据放进工具参数"写成提示词纪律 / 用户约定。零改动，但依赖使用方自觉。

倾向：先做 §1（低风险、纯收益）；§2 属框架级决策，建议按 §14 决策记录的格式单独落定，不要顺手改。

## 3. `RedactCredentials` 的归属（若 §1/§2 要复用它）

现状：它住在 `internal/k8s`，而 `internal/k8s` 是叶子部件——`Zoo/model/k8s-diagnosis.md` §2 写明
"只 import client-go 与标准库，不 import 任何内部包"。

三个选项：

- **a. 让 `web.go` 直接 import `internal/k8s` 用 `k8s.RedactCredentials`**
  门禁允许（`internal/tool/builtin/imports_test.go` 的白名单里有 k8s），但语义不对：
  `web_fetch` 依赖"k8s 采集包"只为拿一个文本函数，会让读者误判模块边界。
- **b. 在 `internal/tool/builtin` 复制一份（3 行）**
  与既有先例一致：`internal/k8s/format.go:410` 正是"本包是叶子部件不能 import agent，故此处重写"。
  代价是两份正则可能漂移（可用同一张用例表缓解）。
- **c. 挪到中立叶子包（如 `internal/redact`，只 import stdlib），k8s 与 builtin 都 import 它**
  最干净，但要让 `internal/k8s` 破一次"不 import 任何内部包"的规约——**属规则变更，需要决策**，不能顺手做。

倾向：当前只有 1 个消费方 + 1 个候选，按项目"最小抽象"的取向选 **b**（复制）；
出现第 3 个消费方再考虑 c。若选 c，要同步 §2 的规约措辞与 `CLAUDE.md`。
