## 1. 现状盘点（已完成）

| 模块 | 职责 |
|---|---|
| `config` | 环境变量优先 + 可选 config.yml，构造注入下游 |
| `provider` | DeepSeek HTTP/SSE、重试、超时（含 retry 子包） |
| `agent` | 多轮对话循环 + 工具调用循环（`maxToolRounds` 兜底、业务失败回灌/框架错误中止）+ 自动持久化 + 预算截断 |
| `tool` | 声明/执行/注册（`Registry`）+ 内置工具（`builtin`）+ `RegisterBuiltins` 集中注册 |
| `session` | 会话持久化：JSONL 每会话一文件（List/Load/Append/Delete/Rewrite），agent 的存储部件 |
| `memory` | 长期记忆：Markdown 文件（`MEMORY.md` + `memory/*.md`）+ bigram 关键词索引（零依赖），`memory_search`/`memory_get`/`memory_save` 工具 + 启动注入 + 归档层受控追加 |
| `persona` | 对话人格：`personas/*.md`（frontmatter + 正文）+ `go:embed`，`--persona` 指定 + 会话头行 meta 绑定（一个对话一个人格） |
| `main` | 组合根装配 + CLI stdin 多轮对话（`--session <id>` 续聊，`--persona <name>` 定人格） |

## 3. 推荐路线（按"离现有代码近 + 价值高 + 复杂度可控"排序）

> **目标维度的选择框架**（与梯队排序互补）：要**对话质量** → 摘要压缩（阶段二）；要**能力边界** → 子代理 / MCP；要**工程治理** → trace（已落地）/ 评测。

### 第一梯队：直接接在现有循环上

1. **会话持久化 + 恢复（session store）**——history 落盘 JSONL（无需 SQLite），重启可 resume。✅ **已实现**（`Zoo/session.md`）：`--session <id>` 续聊。
2. **上下文压缩 / 历史截断（compaction）**——历史超长时截断或摘要，防 context window 溢出。✅ **阶段一已实现**（`Zoo/compaction.md`）：`WithTokenBudget` 估算截断 + 持久化同步重写；阶段二摘要压缩待增强。

### 第二梯队：新模块，复用现有抽象

3. **长期记忆（memory）**——简化版：文件 + 关键词检索即可，先不上向量库。作为工具暴露给模型（`memory_search` / `memory_get`，OpenClaw 同款思路）。✅ **已实现**（`Zoo/model/memory.md`）：`internal/memory` 叶子包（bigram 索引、惰性刷新）+ builtin 工具 + `MEMORY.md` 启动注入 + `SMALL_MEMORY_DIR`。
4. **人格（persona）**——对话风格可命名、可挑选，创建对话时固定。✅ **已实现**（`Zoo/model/persona.md`）：`internal/persona` 叶子包（`go:embed` + frontmatter）+ `--persona` flag + 会话头行 meta 绑定；agent 零改动。
5. **子代理（subagent）**——把"spawn 子会话跑任务再回灌结果"做成一个工具，复用现有循环。
6. **工具轨迹（trace）**——记录每次 tool 调用的入参/结果/耗时，为调试和审计打底。事件源可直接复用 `WithToolObserver`（agent 已具备）。✅ **已实现**（`Zoo/model/trace.md`）：`internal/trace` 叶子包（JSONL 追加）+ `ToolCallEvent` 补耗时/轮次 + 组合根包装 observer 接线。
   - **边界澄清**：工具调用的**本体**（名称/参数/结果）已随会话历史落盘 JSONL（`assistant.ToolCalls` + tool 结果，续聊回灌必需），trace 只补**元数据**（耗时、顺序、失败统计、审计）且**独立成文件**——不写入 session：session 语义是"回灌模型的对话历史"，混入耗时/审计会污染回灌内容（市面同款分离：对话消息 vs Harness trajectory / Codex rollout 元数据）。

### 第三梯队：生态对接（接口不变即可接）

6. **MCP 客户端**——在 `Tool` 接口下加适配器，把外部 MCP server 的工具归一成本地 Tool。
7. **模型路由 / 降级**——多 provider + 失败切换。

### 明确不做（规模不匹配，暂缓）

插件内核（Cordis 式）、向量 RAG、沙箱策略管道、多通道、评测平台——等工具数量和用户量增长后再评估。
- 全屏 TUI / readline 增强 / 命令补全：**暂缓**，接入面维持 CLI；探索结论与触发条件见 `model/tui.md`。

### 演进序（2026-08-25 确认）

> 与梯队互补的时间序：梯队回答"离现有代码多近"，演进序回答"先做哪个"。

- **短期**：命令系统（`internal/command`，权限走 `Permission` 类型 Pass/Ask + 三预留位，见 `model/cli.md` §5）✅ 已实现 2026-08-25 → **`exec` 最小安全版**（重中之重：能力跃迁，必须配每步确认 + 超时 + 白名单，见 `model/tool-extend.md`）✅ 已实现 2026-08-25 → `plan` 工具（Run 级内存 + ctx 注入，见 `model/plan.md`）。
- **中期**：kb 维持**格式约定**（`model/kb.md`，不预建模块；doc 工具落地时若索引/链接解析复杂再抽）→ doc 工具（file_read/doc_search/web_fetch，见 `model/tool-extend.md`）→ **权限横切层**（命令 + 工具统一过 policy，即 roadmap"安全护栏"模块）。
- **长期**：GUI 走 **app-server 模式**（核心保持 CLI/agent，本地 HTTP 服务 + 可选浏览器薄查看器，内核不绑进应用，对齐 Codex "TUI+app-server"）；Electron 式绑内核不做。

关键约定：**权限是横切层**（命令与工具都是受管对象，不是命令系统的私有财产）；权限四决策 = 静态声明 + 仅命令层 + 按工具名 + 平行共享层（不超前）；**exec 不做裸奔版**；**kb 先约定后模块**（判据驱动，见 `model/kb.md` §6）。

## 4. 市面通用模板与新模块开发规范（与既有约定对齐）

### 4.1 新模块三步走（本项目已固化的模板）

1. **文档先行**：先更新 Zoo 设计文档再动代码。
2. **结构依赖显式入参、行为开关走 Option**（CLAUDE.md 已修订的规则）。
3. **依赖单向、隔离点原则不变**；`tool` 与 `provider` 互不感知。
4. **每个模块一个 `New` 对象**，组合根装配。
5. **节点提交 git**——每个"最小可行实现"里程碑即为提交点。

### 4.2 新工具三件套（市面通用模板，已在本项目落地）

> 声明（`Spec`：name/description/JSON Schema 参数）→ 执行（`Result{Data, IsError}`：业务失败回灌给模型自己决策、框架错误才中止）→ 注册（`RegisterBuiltins` 集中注册）。JSON Schema 是 OpenAI/Claude/MCP 的共用底层标准，跨提供商通用；加新工具只需在 builtin 追加一个元素，组合根不改一行。

### 4.3 隔离点模板（新模块接 agent 的首选形态）

> 跨层翻译收敛到唯一文件（如 adapter.go 唯一 import provider）；agent 只认接口/回调不认实现，组合根装配。新模块接 agent 优先用 **"Observer/接口 + 组合根包装"**（如 trace 接 `WithToolObserver`）而非改循环——agent 零改动，依赖方向不破。
