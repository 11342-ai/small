TP类程序的固定模板
- 取出表示为和时间
- 尽早过滤剪枝 (过滤越早，开销越小)
- 跨事件状态走map
- 要送用户态就reverse -> 填写字段 -> submit,reverse返回空，必须判

升级流程:
- 每遇一个 helper 就去 man 7 bpf-helpers 确认返回值和错误语义，返回指针类必须判空。
- 骨架换靶子练
- 认真读 verifier 的加载报错
- 看 libbpf-bootstrap 的其他示例（kprobe/fentry/uprobe），比较同一骨架在不同 attach 类型下的差异
- 能力递进路线：tracepoint（ABI 稳定，最省心）→ kprobe/fentry（覆盖任意内核函数，但要用 CO-RE 处理字段漂移）→ 用户态 Go 侧（ringbuf 消费、map 查询、attach/detach 生命周期）。只写 bpf.c 不碰用户态，是走不远的
helper 查内核文档，tp 名与字段查 tracefs 的 format 文件，map 语法与类型查 libbpf 文档，骨架靠反复换靶子固化。

###### eBPF 模块：vmlinux.h 与 .o 的获取与重建
两个产物不入库，克隆后需本地生成。vmlinux.h 是内核类型定义，随内核版本变化；
C/ProcessObservation.o 由 C 源码编译，再被 Go 侧 //go:embed 打进二进制。

**依赖**
clang（需带 BPF target）、bpftool、libbpf 开发头文件，且运行内核开启 BTF。
ls /sys/kernel/btf/vmlinux      # 有输出即支持

**生成 vmlinux.h**
cd internal/ebpf
bpftool btf dump file /sys/kernel/btf/vmlinux format c > C/vmlinux.h
生成失败会留下 0 字节空文件，后续编译只报"类型找不到"，看不出根因。落盘后确认大小。

**重建 .o**
编译命令已写成 go:generate，位于 probe_SchedProcessFork.go：
//go:generate clang -O2 -g -target bpf -Wall -Wno-missing-declarations -c C/ProcessObservation.bpf.c -o C/ProcessObservation.o

在模块目录执行：
cd internal/ebpf
go generate ./...

**验证**
ls -l C/ProcessObservation.o    # 非空
go build ./...                  # embed 能取到，构建通过

**备注**
C/Makefile 是早期探针残留，all 目标指向已不存在的 min_open.bpf.c，不可用；
其中的 vmlinux.h 目标与本文第一步等价。重建以 go:generate 为准。
