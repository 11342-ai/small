TP类程序的固定模板
- 取出表示为和时间
- 尽早过滤剪枝 (过滤越早，开销越小)
- 跨事件状态走map
- 要送用户态就reverse -> 填写字段 -> submit,reverse返回空，必须判

升级流程:
- 每遇一个 helper 就去 man 7 bpf-helpers 确认返回值和错误语义，返回指针类必须判空。
- 骨架换靶子练
- 认真读 verifier 的加载报错
- 看 libbpf-bootstrap 的其他示例（kprobe/fentry/uprobe），比较同一骨架在不同 attach 类型下的差异
- 能力递进路线：tracepoint（ABI 稳定，最省心）→ kprobe/fentry（覆盖任意内核函数，但要用 CO-RE 处理字段漂移）→ 用户态 Go 侧（ringbuf 消费、map 查询、attach/detach 生命周期）。只写 bpf.c 不碰用户态，是走不远的
helper 查内核文档，tp 名与字段查 tracefs 的 format 文件，map 语法与类型查 libbpf 文档，骨架靠反复换靶子固化。

查找挂载点与 helper 的查法（不靠背）
- bpftrace -l 就是内核当前可用挂载点的清单，支持通配，最省事的入口：
  bpftrace -l 'tracepoint:*open*'
  bpftrace -l 'kprobe:*unlink*'
  bpftrace -l 'fentry:*open*'
  bpftrace -l 'uprobe:/usr/bin/bash:*readline*'
- root 下的权威扁平清单：
  sudo grep -c . /sys/kernel/tracing/available_events                      # 全部 tracepoint（subsys:event）
  sudo grep -w do_sys_openat2 /sys/kernel/tracing/available_filter_functions   # 可挂 kprobe/fentry 的函数
  grep -w do_sys_openat2 /proc/kallsyms                                    # 非 root 可见符号名（地址为 0）
- ctx 里有什么：format 给字段名/类型/ID，结构体名与内存布局在 BTF（vmlinux.h），两边合起来才是完整信息
  sudo cat /sys/kernel/tracing/events/syscalls/sys_enter_openat/format     # name + ID + 每个字段的 offset/size/signed（注意：文件里没有 struct 定义）
  grep -n -A 6 "struct trace_event_raw_sys_enter " C/vmlinux.h             # ctx 结构体（vmlinux.h 由 /sys/kernel/btf/vmlinux dump 而来）
  bpftrace -lv 'tracepoint:syscalls:sys_enter_openat'                      # 字段名 + 真实类型的说明书
  坑：syscall 类 tp 没有 per-syscall 的独立 ctx 结构，ctx 就是这一个 args[6]；format 里的 dfd@16 / filename@24 / flags@32 / mode@40 正好是 args[0..3]（16 起，每槽 8 字节），所以字段看着统一是 u64，语义要回查 man 2 openat（args[1] 是用户态指针，要 bpf_probe_read_user_str）
- 先验证再落地：写 .bpf.c 之前先用 bpftrace 一行确认点会触发、字段拿得到，免得"编完 load 完才发现看不到"
  sudo bpftrace -e 'tracepoint:syscalls:sys_enter_openat { printf("%s %s\n", comm, str(args.filename)); }'
  sudo bpftrace -e 'kprobe:*open* { @[probe] = count(); }'               # 反向找"哪个函数真被调到"
  sudo bpftrace -e 'kprobe:do_sys_openat2 { print(kstack); exit(); }'    # 看调用链
- helper 的四个来源：
  bpftool feature list_builtins helpers                                    # 全量名单（不需要 root），按 helper ID 从 0 排
  man 7 bpf-helpers                                                        # 权威：签名/返回值/错误语义
  grep -n -i "probe_read\|get_current_pid" /usr/include/bpf/bpf_helper_defs.h
  声明行尾 "(void *) 114" 里的数字就是 helper ID（拿它和 list_builtins 的排序对上）
  sudo bpftool feature probe kernel                                        # 本内核实际支持情况（非 root 报缺 CAP_SYS_ADMIN；加 full 才探测 printk 这类）
- 报错即字典：unknown func bpf_xxx#NN = 该程序类型没这个 helper；cannot call GPL-restricted = helper 是 GPL-only（license 要写 GPL）；R1 type=fp expected=map_ptr = 参数类型不对，回 man 看签名
- 前缀即语义：probe_read* 读内核内存、probe_read_user* 读用户内存、get_current_* 取上下文、map_* 操作 map、ringbuf_* 送用户态
- 标准答案库：bcc 仓库的 libbpf-tools/*.bpf.c（opensnoop/execsnoop/biostacks 全套），同类需求直接对答案
- 选点原则：先问"数据在谁手里"——内核函数的参数/返回值 → kprobe/fentry；内核现成的稳定 ABI 事件 → tracepoint（先读 format）；用户态函数 → uprobe；报文 → XDP/TC；拿不准 → bpftrace -l 枚举 + 一行脚本验证

helper 怎么用：参数、类型、怎么配合
- 参数与返回值：bpf_helper_defs.h 的注释就是内核原版文档（含 Returns 与错误约定），签名即参数类型；返回指针的（map_lookup_elem / ringbuf_reserve）必须判空，返回 long 的读类 helper 负数即 errno
- 签名里的结构体：一律去 BTF（vmlinux.h）grep，别靠脑记
  grep -n -A 30 "^struct __sk_buff {" C/vmlinux.h
- 指针方向决定用哪个 family：syscall 参数等用户态地址 → probe_read_user(_str)；map value、内核结构体 → probe_read_kernel(_str)；分不清或老内核 → probe_read（新内核已边缘化）
- 数据存哪：只能是自己栈上（BPF 栈上限 512B，故 char buf[256] 配 sizeof(buf)）、map value 或 ringbuf 预留区
- 三条硬约束：返回值必须判；传进去的内存要 verifier 认为可写且够大；map value 指针跨 helper 调用可能失效，会被要求重新 lookup
- 按数据流选（不按字母背）：取上下文 → 过滤剪枝 → 搬运 → 聚合/推送 → 用户态消费
  取上下文：get_current_pid_tgid / get_current_comm / get_current_task / get_current_uid_gid / get_smp_processor_id / ktime_get_ns
  搬运：probe_read_user_str / probe_read_kernel / skb_load_bytes
  聚合：map_lookup_elem + map_update_elem（或 .bss 全局量配原子）
  推送：ringbuf_reserve + submit/discard（老写法 perf_event_output；printk 只当调试）
  栈：get_stackid（配 stack trace map）/ get_stack
  控制：send_signal / override_return（kprobe）
- 三级组合，从简到正式：
  1) 只打日志：get_current_pid_tgid + printk（≤3 参数、%s 只能打 BPF 栈上的字符串、所有程序共享 trace_pipe）
  2) 打文件名：probe_read_user_str 拷到栈上再 printk
     char buf[256];
     long len = bpf_probe_read_user_str(buf, sizeof(buf), (void *)ctx->args[1]);
     if (len < 0)
         return 0;
     bpf_printk("openat %s\n", buf);
  3) 正式：ringbuf_reserve → 填字段 → submit（填失败则 discard），用户态侧消费
     struct event *e = bpf_ringbuf_reserve(&rb, sizeof(*e), 0);
     if (!e)
         return 0;                            /* reserve 必须判空 */
     ...填 e->pid / e->comm / e->path...
     if (填失败) { bpf_ringbuf_discard(e, 0); return 0; }
     bpf_ringbuf_submit(e, 0);                /* reserve 之后 submit/discard 必须调、且只调一个 */
- 配合三条硬规则：reserve/submit/discard 成对，漏调丢 slot；跨事件的状态放 map 或全局量（局部变量活不过本次调用）；别跨 helper 长期持有 map value 指针、别把 helper 调用塞进循环
