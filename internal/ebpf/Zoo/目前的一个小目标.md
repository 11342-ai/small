##### 系统调用异常/耗时
**问题名称和典型现象**
某个服务系统调用非常频繁或者单次 syscall 明显变慢
安全可复现方式或触发条件
程序循环执行 read/write/openat/futex 等系统调用。

**需要关注的观测指标**
syscall 次数、错误码、耗时、调用类型、PID/TGID。

**eBPF 挂载点**
优先：
tracepoint:raw_syscalls:sys_enter
tracepoint:raw_syscalls:sys_exit

特定 syscall 也可以使用：
tracepoint:syscalls:sys_enter_openat
tracepoint:syscalls:sys_exit_openat

为什么挂这里
enter/exit 天然形成一次 syscall 的开始/结束边界，适合做耗时关联。

**采集数据**
enter：
pid/tgid
syscall id
timestamp

exit：
syscall id
return value
timestamp
latency = exit_ts - enter_ts

建议只追踪目标 PID/TGID 或指定 syscall。

保存 map
hash<pid_tgid, start_ns>：enter 保存开始时间
percpu_hash/syscall_id：统计次数
hash<syscall_id, histogram>：延迟分布
ringbuf：超过阈值的慢 syscall
判断边界和常见坑

不能只看平均耗时；syscall 往往是长尾问题。并且 syscall 很高频，必须过滤，否则 eBPF 自己产生的开销可能明显增加。


****

syscall 次数/速率。基准：正常时按 syscall id、PID/TGID 的每秒计数。触发：某类调用或某进程突增。处理：per-CPU hash 计 u64。流式输出：每 5 秒聚合一次，只出 top N，不逐条打。

错误码分布。基准：正常 errno 比例。触发：EINVAL、ENOENT、EPERM、EBADF 等异常码增多，或错误率超阈值。处理：hash<syscall_id, errno> 计数。流式输出：周期增量，异常码变化时才打印。

延迟直方图。基准：各 syscall 的 P50、P95、P99、max。触发：P99 或 max 超阈值、分位漂移。处理：hash<syscall_id, log2 histogram>。流式输出：周期导出直方图，算分位，不输出单次。

慢 syscall 事件。基准：阈值如 1ms、10ms、100ms。触发：latency 超阈值。处理：enter 存 map<pid_tgid,start_ns>，exit 算差值，ringbuf 只送慢事件。流式输出：限流或采样，带 pid/tgid、syscall id、latency、ret。

解决的点：区分是调用太频繁，还是单次太慢；并定位到哪个 syscall、哪个进程、什么错误码、长尾在哪。个人项目够用。必须按 PID/TGID 或 syscall 过滤。
