##### 进程创建与退出
**问题名称和典型现象**
进程频繁创建/退出，例如 Web 服务不断 fork worker，表现为 PID 数量快速变化、进程创建开销增加。

**安全可复现方式或触发条件**
循环执行：
sh -c 'sleep 0.01'
或者 Python/Go 不断创建短生命周期子进程。

**需要关注的观测指标**
创建次数、退出次数、进程生命周期、父子关系、UID、comm。

**eBPF 挂载点**
优先：
tracepoint:sched:sched_process_fork
tracepoint:sched:sched_process_exit

**为什么挂这里**
fork/exit 本身就是明确的生命周期边界，能直接得到父子 PID、退出状态等信息，不需要依赖函数内部实现。

**采集数据**

关键字段：
pid/tgid
parent_pid
uid
comm
timestamp
exit_code

创建时保存 start_ns，exit 时：
lifetime = now_ns - start_ns
可以按 PID 过滤目标进程。

**保存 map**
hash<pid, start_info>：保存活跃进程
percpu_array：总创建/退出计数
ringbuf：输出进程生命周期事件

**判断边界和常见坑**
PID 会复用，所以不要只把 PID 当永久唯一 ID；长时间运行的程序必须及时删除退出 PID。进程和线程也要区分 TGID/PID。


*****

目前的一个缺失
- fork侧缺乏 timestamp | uid | exit册comm[没有完成赋值] | exit_code | tgid
- e->parent_pid = task->real_parent->pid; 下一行又被覆盖，重复且口径是 tid
- fork 侧写的 parent_tgid 是 tgid，两个事件父字段口径不一致
- exit 事件没有 tgid，分不清"线程退出"和"进程退出"。sched_process_exit 每个线程退出都触发，多线程程序会淹掉真正的进程退出。


****

1. 创建/退出速率。基准：稳态每秒 fork/exit 次数。触发：1 秒窗口突增或超阈值。数据：percpu_array 分别计创建、退出。流式：每秒输出 delta 和速率，不逐事件打印。解决：判断是否真的频繁创建退出。
2. 短命进程比例与生命周期。基准：正常 worker 存活时间。触发：lifetime 低于阈值且占比升高。数据：hash<pid,start_ns>，exit 时算 now-start；ringbuf 发退出事件。流式：按 lifetime 分桶，或只输出短命样本。解决：看创建开销是否来自短生命周期进程。
3. 活跃进程数。基准：稳定并发数。触发：持续上升或大幅波动。数据：活跃 hash size，或 fork/exit 净差。流式：周期输出 size 和净增。解决：判断创建退出是否失衡、是否造成 PID 压力。
4. 父子/comm 创建来源。基准：正常 parent_pid、comm 分布。触发：某 parent_pid 或 comm 创建速率异常。数据：事件带 pid/tgid、parent_pid、uid、comm、exit_code。流式：用户态按 parent/comm 聚合，每秒输出 top 创建者。解决：定位谁在 fork，并区分 TGID/PID。
